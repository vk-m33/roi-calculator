# BUG-006: PDF Export fails silently in Tauri desktop app (WebView2 environment)
Status: RESOLVED
Severity: High
Feature: PDF Export
File: src/utils/exportPDF.js
Reporter: tester

## Description
In the Tauri v2 desktop build (WebView2 renderer), PDF export used `window.__TAURI__` for Tauri
environment detection. In Tauri v2, `window.__TAURI__` is no longer reliably set on
`window` in WebView2; the canonical property is `window.__TAURI_INTERNALS__`. As a result,
the Tauri code path (native save dialog + `writeFile`) was never entered, and the fallback
`doc.save()` was called instead — which silently fails in WebView2 because the browser blob
download mechanism is not available.

Additionally, the earlier implementation lacked `@tauri-apps/plugin-fs` / `@tauri-apps/plugin-dialog`
imports, the corresponding Rust plugin registrations in `lib.rs`, and the `fs:allow-write-file`
capability in `default.json`, all of which are required for file writes to succeed.

## Steps to Reproduce
1. Build and run the Tauri desktop app (`npm run tauri dev` or the release build).
2. Enter valid ROI inputs and click "Export PDF".
3. Observe: no save dialog appears; no file is written; no error is shown.

## Expected Result
A native OS Save dialog opens, the user chooses a destination, and a valid PDF file is written
to disk using `writeFile` from `tauri-plugin-fs`.

## Actual Result (before fix)
`doc.save()` was called and silently failed because WebView2 does not support blob-URL
browser downloads. No file was created and no feedback was given to the user.

## Root Cause
- Tauri v2 sets `window.__TAURI_INTERNALS__` rather than `window.__TAURI__` inside WebView2.
- Missing Rust plugin registrations (`tauri_plugin_dialog::init()`, `tauri_plugin_fs::init()`).
- Missing capability permissions (`fs:default`, `fs:allow-write-file`).
- Missing npm package imports (`@tauri-apps/plugin-dialog`, `@tauri-apps/plugin-fs`).

## Resolution
Fixed in `src/utils/exportPDF.js`:
- Detection changed to `typeof window.__TAURI_INTERNALS__ !== 'undefined'`.
- Top-level imports added for `save as tauriSave` from `@tauri-apps/plugin-dialog` and
  `writeFile` from `@tauri-apps/plugin-fs`.
- Tauri path now calls `tauriSave()` for the native dialog, then `writeFile(filePath, new Uint8Array(pdfBytes))`.
- A `try/catch` surfaces failures via `alert()` so errors are visible to the user.
- Web fallback `doc.save()` retained for the browser build.

Supporting changes:
- `src-tauri/src/lib.rs`: `tauri_plugin_dialog::init()` and `tauri_plugin_fs::init()` registered.
- `src-tauri/Cargo.toml`: `tauri-plugin-dialog = "2"` and `tauri-plugin-fs = "2"` added.
- `src-tauri/capabilities/default.json`: `fs:default` and `fs:allow-write-file` permissions added.

All verification checks PASS as of 2026-07-30.
