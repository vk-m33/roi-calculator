# BUG-002: Comparison Mode — scenario labels are hardcoded, rename not implemented
Status: RESOLVED
Severity: High
Feature: Comparison Mode
File: src/components/CalculatorCore.jsx:72-83
Reporter: tester

## Description
The `ScenarioLabel` component (lines 72-83) renders hardcoded strings "Scenario A" and "Scenario B". There is no editable input that lets the user rename a scenario to something meaningful (e.g. "Current Process" vs "Proposed Solution").

## Steps to Reproduce
1. Click "Compare scenarios" to enter comparison mode
2. Look at the section headers above each scenario column — they read "Scenario A" and "Scenario B" with no way to edit them

## Expected Result
Each scenario should have an inline-editable label. Clicking the label (or an edit icon next to it) should reveal a text input; blurring the input should confirm the new name and update the display.

## Actual Result
`ScenarioLabel` component returns a static `<div>` with a hard-coded "Scenario A" / "Scenario B" string and a conditional "Better ROI" badge. No state, no input, no edit handler.

## Resolution
Rewrote `ScenarioLabel` in `CalculatorCore.jsx` to be inline-editable: clicking the label swaps it for a text input that commits on blur/Enter and reverts on Escape. Added `labelA`/`labelB` state (defaulting to "Scenario A"/"Scenario B") in `CalculatorCore` and passed them as `label` and `onRename` props to each `ScenarioLabel` instance.
